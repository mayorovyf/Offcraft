# Диагностический OpenGL-стенд

[English](../standalone.md)

[Документация](index.md) · [Обзор проекта](README.md)

Standalone-пример проверяет скрытый графический контекст без Minecraft: Java 21 + LWJGL 3.3.6, OpenGL 3.3 core и рендер по запросу в отдельный framebuffer 640×360.

## Сборка и запуск стенда

Требуются JDK 21+ и Maven.

```powershell
cd C:\Projects\MinecraftMods\Offcraft
mvn.cmd -B -ntp package
java -jar dist\offcraft-1.0.0-standalone-windows-x64.jar
```

Исполняемый JAR включает LWJGL и Windows x64 native-библиотеки. Он записывается прямо в корневой `dist/`; промежуточные файлы Maven остаются в `target/`. Версионирование и правила имён: [development.md](development.md#версионирование).

Ввести команды в том же терминале:

```text
status
render
render output/frame with spaces.png
status
quit
```

- `render` — сохранить `output/frame-0001.png`, затем `frame-0002.png` и т. д.
- `render <путь>` — сохранить PNG по указанному пути. Пробелы допустимы, кавычки не нужны. Относительные пути считаются от рабочего каталога.
- `status` — PID, видимость окна, число успешно сохранённых кадров и размер рендера.
- `help` — краткая справка.
- `quit` или EOF stdin — завершить процесс и освободить ресурсы.

В новом процессе нумерация начинается заново; существующие файлы с теми же именами перезаписываются. Пример рассчитан на один процесс в рабочем каталоге.

Терминал запуска остаётся видимым, графическое окно не создаётся в видимом состоянии. Контроллер может запускать Java с перенаправленными stdin/stdout/stderr без нового консольного окна и отправлять те же команды через stdin. Закрытие stdin завершает приложение.

## Поведение стенда

Все GLFW/OpenGL-вызовы выполняются на основном потоке. Отдельный daemon-поток читает stdin и передаёт команды через ограниченную очередь. В ожидании запросов приложение обрабатывает события примерно раз в 50 мс, но не рисует и не кодирует изображения.

Каждый успешный запрос рендера меняет положение цветного треугольника, цвет фона и маркер в левом верхнем углу. Нечётные кадры имеют оранжевый маркер и треугольник слева, чётные — голубой маркер и треугольник справа. Это позволяет отличить свежий кадр и проверить вертикальную ориентацию.

Изображения считываются из FBO через `glReadPixels`, не с рабочего стола. Строки переворачиваются для PNG. Буфер чтения и изображение переиспользуются. `gpu_readback_ms` измеряет CPU wall-clock время подачи команд рендера и синхронного чтения пикселей, а не чистое время GPU. `total_ms` дополнительно включает преобразование пикселей, кодирование PNG и запись файла. Ошибки команды рендера выводятся в stderr; после них можно продолжать работу.

Исторические результаты стенда и границы проверки: [verification.md](verification.md). Успех стенда не подтверждает работу Minecraft-мода.
