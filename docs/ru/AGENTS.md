# AGENTS.md

[English](../../AGENTS.md)

## Постоянный контекст

- Offcraft управляет настоящим клиентом Minecraft 1.21.1 через JSONL; целевая среда — Windows x64 и Java 21. Скрытое окно не устраняет потребность в графической сессии и OpenGL.
- `common/` — единственная реализация игровых возможностей. `fabric/`, `forge/`, `neoforge/` — отдельные Gradle-проекты с bootstrap/метаданными; каждый JAR включает common. Не дублируйте игровую логику по загрузчикам и не добавляйте runtime Architectury API без явной необходимости.
- Корневой `pom.xml` и `src/` — отдельный диагностический LWJGL-стенд, не сборка модов. `mcp/` — Node.js 22+ stdio-адаптер без npm-зависимостей, который запускает настоящий клиент.

## Инварианты изменений

- Minecraft, GLFW/OpenGL, игровой ввод и capture выполняются на render thread. Поток stdin только передаёт строки в ограниченную очередь.
- Действия измеряются игровыми тиками и используют vanilla-механику. Не заменяйте ввод телепортацией, а операции контейнера — прямой записью стеков.
- Завершение, прерывание, отмена, quit, EOF и shutdown должны освобождать управляемые кнопки и очереди нажатий.
- `accepted` — принятие, не успех. Сохраняйте корреляцию ID и единственный терминальный ответ `completed/error` для принятого запроса; повтор активного ID не создаёт второй терминальный ответ.
- Одновременно активна одна длительная изменяющая команда; доступные во время неё наблюдение, status и отмена не должны блокироваться за действием.
- PNG должен описывать свежий завершённый кадр; ответ с capture приходит после записи файла. Reduced-отрисовка не должна останавливать игровые/сетевые тики.
- Окно создаётся скрытым, не прячется после показа. Не возвращайте fullscreen, захват курсора или автопаузу из-за отсутствия фокуса.
- Клиентское наблюдение, отправка пакета и локальное предсказание — не серверное подтверждение. Development-профиль — не авторизованный Microsoft-аккаунт.

## Порядок работы

- Сначала прочитайте затронутый код и профильный документ ниже. Сохраняйте существующие соглашения; меняйте только относящееся к задаче.
- Изменение common затрагивает все три загрузчика. Изменение команды требует согласованных правок реализации, MCP-схем, затронутых контрактных тестов и справочника JSONL.
- Не перезаписывайте чужие изменения, миры или конфигурацию. Не выполняйте автоматически stash, reset, очистку, переключение поверх незавершённых изменений или принудительную отправку.
- До Git-операций прочитайте [docs/git.md](git.md). Правила веток — политика, не доказательство наличия `dev`, remote или защиты веток. Коммиты, слияния, теги и публикацию выполняйте только при разрешении в рамках задачи.
- Проверяйте фактический изменённый путь исполнения. Сборка и тестовый транспорт не заменяют smoke настоящего клиента; для документации достаточно проверки содержимого и ссылок.
- Сообщайте только выполненные проверки с конкретными результатами и ограничениями. Исторические записи в docs не являются новым PASS.
- После изменений обновляйте соответствующую документацию. Основные документы ведите на английском, русские копии храните в `docs/ru/` и обновляйте вместе с оригиналами. README сохраняйте ознакомительным; подробные процедуры и технические контракты храните в docs, а не раздувайте этот файл.
